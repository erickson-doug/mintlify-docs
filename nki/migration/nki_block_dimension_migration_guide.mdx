SBUF/PSUM tensors in NKI used to allow block dimensions in front of the partition dimension. The block-dimension support has been removed for these reasons:

- Removing block dimensions doesn't hurt the expressivity of NKI.
- Block dimension is a pure software concept and has no direct hardware mapping.
- The block dimension is unintuitive and causes confusion.
- Using block dimension has no inherent performance benefit; in particular, using block dimension has no relationship with memory throughput whatsoever.
- Multi-buffering is implicit with block dimension. Removing block dimensions makes multi-buffering more natural.

This document first explains the semantics of block dimensions in detail, then provides guidance for migrating existing code that used them while maintaining functional correctness and performance.

## What are block dimensions?

Consider the following NKI tensor:

```python
a = nl.ndarray((4, 8, nl.par_dim(128), 2, 512), buffer=nl.sbuf)

# - (4, 8):   (B) block dimensions
# - 128:      (P) partition dimension
# - (2, 512): (F) free dimension
```

A NKI tensor has three types of dimensions: `(B, P, F)`. The partition dimension maps to the partition dimension of the physical memory, and the free dimensions describe how data is organized in each SBUF/PSUM partition. The block dimensions described how many physical `(P, F)` tiles the tensor has.

The block dimension of tensors was a **logical** dimension and a pure software concept. The compiler analyzes the memory dependency and allocates physical addresses to each tile. **This means the physical tiles may not be alive in memory simultaneously** — in most cases they aren't. Consider the following code snippet that accesses tensor `a`:

```python
@nki.jit
def exp_func(inp):
    output = nl.ndarray((4, 8, 128, 2, 512), dtype=float32, buffer=nl.shared_hbm)
    a = nl.ndarray((4, 8, nl.par_dim(128), 2, 512), dtype=float32, buffer=nl.sbuf)
    for i in range(4):
        for j in range(8):
            a[i, j] = nl.load(inp[i, j])
            a[i, j] = nl.exp(a[i, j])
            nl.store(output[i, j], value=result)
```

At the minimum, only 1 physical tile of `a` needs to be alive. Then execution is completely serialized. Essentially, all physical tiles would have the exact same memory address:

```text
Physical address map

output[0, 0] --> Partition 0 - 128, Free 0 - 2048B
output[0, 1] --> Partition 0 - 128, Free 0 - 2048B
...
```

Instead, the compiler could choose to allocate 2 physical tiles to `a`, so the DMA copy from HBM to SBUF can overlap with the exponential operation. **The block dimension allowed the compiler to perform a space-time trade-off at liberty.**

```text
Physical address map

output[0, 0] --> Partition 0 - 128, Free 0    - 2048B
output[0, 1] --> Partition 0 - 128, Free 2048 - 4096B
output[0, 2] --> Partition 0 - 128, Free 0    - 2048B
output[0, 3] --> Partition 0 - 128, Free 2048 - 4096B
...
```

When performing the migration, it's important to understand the dependency relationship between blocks and choose the correct migration method accordingly.

## Migration for SBUF tensors

### If blocks need to be alive at the same time, move the block dimension into the free dimension

```python
a = nl.ndarray((8, par_dim(128), 512), buffer=nl.sbuf, dtype=bfloat16)

# ----> Migrate to
a = nl.ndarray((128, 8, 512), buffer=nl.sbuf, dtype=bfloat16)
```

As an example, all 8 blocks of `add_buf` need to be alive at the same time when the first for loop finishes. The block dimension needs to be folded into the free dimension.

```python
@nki.jit
def sb_blocks(inp):
    res = nl.ndarray(shape=(8, 128, 512), dtype=inp.dtype, buffer=nl.shared_hbm)
    add_buf = nl.ndarray(shape=(8, nl.par_dim(128), 512), dtype=inp.dtype, buffer=nl.sbuf)
    for i in range(8):
        add_buf[i] = nl.load(inp[i])
    for i in range(8):
        nl.store(res[i], add_buf[i])
    return res

# Migrate to:
@nki.jit
def sb_blocks_migrated(inp):
    res = nl.ndarray(shape=(8, 128, 512), dtype=inp.dtype, buffer=nl.shared_hbm)
    add_buf = nl.ndarray(shape=(128, 8, 512), dtype=inp.dtype, buffer=nl.sbuf)
    for i in range(8):
        add_buf[0:128, i, 0:512] = nl.load(inp[i])
    for i in range(8):
        nl.store(res[i], add_buf[0:128, i, 0:512])
    return res
```

### If blocks don't need to be alive at the same time, remove the block dimension and hoist it down

```python
a = nl.ndarray((8, par_dim(128), 256))
for i in nl.affine_range(8):
    # do something with a[i]
    ...

# Should be transformed to:
for i in nl.affine_range(8):
    a = nl.ndarray((128, 256))
    # do something with a
    ...
```

As an example, all 8 blocks of `add_buf` don't need to be alive at the same time. Remove the block dimension and hoist the tensor down inside the loop:

```python
@nki.jit
def sb_blocks(inp):
    res = nl.ndarray(shape=(8, 128, 512), dtype=inp.dtype, buffer=nl.shared_hbm)
    add_buf = nl.ndarray(shape=(8, nl.par_dim(128), 512), dtype=inp.dtype, buffer=nl.sbuf)
    for i in range(8):
        add_buf[i] = nl.load(inp[i])
        nl.store(res[i], add_buf[i])
    return res

# Migrate to:
@nki.jit
def sb_blocks_migrated(inp):
    res = nl.ndarray(shape=(8, 128, 512), dtype=inp.dtype, buffer=nl.shared_hbm)
    for i in range(8):
        add_buf = nl.ndarray(shape=(128, 512), dtype=inp.dtype, buffer=nl.sbuf)
        add_buf[0:128, 0:512] = nl.load(inp[i])
        nl.store(res[i], add_buf[0:128, 0:512])
    return res
```

<Warning>
  To preserve performance, hoist the tensor down inside the loop.
</Warning>

The dependency relationship between loop iterations differs between `sb_blocks_migrated` and the following `sb_blocks_migrated_incorrect`:

```python
@nki.jit
def sb_blocks_migrated_incorrect(inp):
    res = nl.ndarray(shape=(8, 128, 512), dtype=inp.dtype, buffer=nl.shared_hbm)
    add_buf = nl.ndarray(shape=(128, 512), dtype=inp.dtype, buffer=nl.sbuf)
    for i in range(8):
        add_buf[0:128, 0:512] = nl.load(inp[i])
        nl.store(res[i], add_buf[0:128, 0:512])
    return res
```

In `sb_blocks_migrated`, the compiler could unroll the loop and materialize multiple copies of the tensor `add_buf`. However, in `sb_blocks_migrated_incorrect`, execution is serialized because the loop carries a dependency on `add_buf`.

## Migration of direct allocation and multi-buffering

With block dimensions, we allocated interleaved addresses for blocks to achieve multi-buffering:

```python
def interleave_alloc_func(idx, pdim_size, fdim_size):
    """
    This function assumes 1D block dimension, and allocates a unique
    address by modulo of 2.

    For a tensor of 4 blocks, block 0 and 2 have the same address, while
    block 1 and 3 have the same address — different from 0 and 2.
    """
    # unpack the tuple
    idx, = idx

    # hard-code to partition 0, since each tile takes up 128 partitions
    start_partition = 0

    return (start_partition, (idx % 2) * fdim_size)

@nki.jit
def copy_func(inp):
    output = nl.ndarray((4, 128, 512), dtype=float32, buffer=nl.shared_hbm)
    a = nl.ndarray((4, nl.par_dim(128), 512), dtype=float32, buffer=ncc.sbuf.alloc(interleave_alloc_func))
    for i in range(4):
        a[i] = nl.load(inp[i])
        nl.store(output[i], value=a[i])
```

After removing the block dimension, write the following to implement the same multi-buffering — actually more natural and closer to what you'd do on CPU:

```python
def interleave_alloc_func(idx, pdim_size, fdim_size):
    """
    This function assumes 1D block dimension, and allocates a unique
    address by modulo of 2.

    For a tensor of 4 blocks, block 0 and 2 have the same address, while
    block 1 and 3 have the same address — different from 0 and 2.
    """
    # unpack the tuple
    assert idx == ()  # No block dimension

    # hard-code to partition 0, since each tile takes up 128 partitions
    start_partition = 0

    return (start_partition, (idx % 2) * fdim_size)

@nki.compiler.skip_middle_end_transformations
@nki.jit
def exp_func(inp):
    output = nl.ndarray((4, 128, 512), dtype=nl.float32, buffer=nl.shared_hbm)
    a = nl.ndarray((128, 2, 512), dtype=nl.float32, buffer=ncc.sbuf.alloc(interleave_alloc_func))
    for i in range(4):
        a[0:128, i % 2, 0:512] = nl.load(inp[i])
        nl.store(output[i], value=a[0:128, i % 2, 0:512])
```
